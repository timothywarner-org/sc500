# Lesson 13: Microsoft Sentinel I: Workspace, Connectors, and Log Ingestion

**Exam SC-500 domain:** Manage and monitor security posture (20-25%)  
**Study guide sections:** Implement activity and event collection in Microsoft Sentinel

## Learning objectives

- 13.1 Create and connect Microsoft Sentinel workspaces, and assign Microsoft Sentinel roles for analyst and engineer responsibilities
- 13.2 Implement and use content hub solutions, and configure and use Microsoft data connectors for Azure resources, Microsoft Entra, Microsoft 365, and Defender XDR
- 13.3 Implement and configure syslog and Common Event Format (CEF) event collection, and collect Windows Security events using data collection rules and Windows Event Forwarding (WEF)
- 13.4 Create custom log tables for ingested data and implement data retention in Microsoft Sentinel data stores

## Hands-on practice

Every demo in this lesson is work you can repeat in your own subscription, mostly in the Azure portal or the Microsoft admin centers. Do each one yourself after you watch it, because clicking through a configuration sticks far better than reading about it.

The step-by-step walkthrough and any lab files for this lesson land in [`demos/`](demos/) after the lesson publishes. Watch the [changelog](../../CHANGELOG.md) for updates.

## Before you start

- An Azure subscription you control, ideally a dedicated sandbox with a budget alert
- A resource group just for this lesson, so cleanup is a single delete
- Microsoft Sentinel charges for the data you ingest and retain, so keep your test data small.
